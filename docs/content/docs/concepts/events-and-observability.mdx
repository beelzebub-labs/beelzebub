---
title: Events And Observability
description: Collect interaction evidence through logs, Prometheus, RabbitMQ, and optional Cloud reporting.
---

Every interaction becomes a tracer event, but the fields available depend on the protocol strategy. Binary TCP input that is not valid UTF-8 is preserved in `CommandRaw` as reversible `\xNN` escapes. A wire plugin may enrich the event’s `Metadata` map; the built-in VNC plugin uses it for a correlated challenge, response, and authorized-analysis representation.

HTTP request events include bounded request-body descriptors in `Metadata`: `body.request.size` is the number of bytes retained (up to 1 MiB), `body.request.truncated` marks input longer than that bound, and `body.request.read_error` distinguishes a read failure from a complete capture. `http.response.status` and `body.response.size` describe the response selected by the handler. They are measured before the HTTP server writes the response, so they do not prove how many bytes reached the network or were received by the client. Core descriptor keys use dot-prefixed domains; plugins should use their own prefix to avoid collisions.

Prometheus exposes `beelzebub_events_total` plus protocol counters such as `beelzebub_ssh_events_total`, `beelzebub_http_events_total`, `beelzebub_tcp_events_total`, `beelzebub_telnet_events_total`, and `beelzebub_mcp_events_total` at the configured endpoint (default `:2112/metrics`).

RabbitMQ publishes structured JSON to the `event` queue when enabled. Cloud reporting is optional; read [Cloud integration](../../operations/integrations) before sending captured data outside the host.
